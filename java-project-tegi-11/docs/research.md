# Research: Электрондық қолтаңба утилитасы

Тақырып 11 · «Комп жүйе қауіпсіздігі», ИП2408k · RSA-2048, SHA256withRSA, PEM

## 1. Зерттелген орта (ұйым)

Утилита ұйымның құжат айналымы үшін жасалды: кадр бөлімінің бұйрығы, шарт, есеп сияқты файлдарды жіберген кезде алушы екі нәрсені білуі керек.

1. Құжат жолда өзгертілмеген бе (тұтастық).
2. Құжатты шынымен сол қызметкер жіберді ме (авторлық).

Қағаз құжатта мұны қолмен қойылған қол және мөр қамтамасыз етеді. Электрондық файлда мұны криптографиялық қолтаңба істейді.

**Қазіргі мәселелер (ұйымда):**
- Файлды электрондық поштамен жібергенде оны кім болса да өзгерте алады.
- Жіберушінің атынан жалған файл жіберу мүмкін.
- Қызметкер құжатқа қол қойғанын кейін жоққа шығара алады.

**Шешім:** RSA-2048 кілт жұбы мен SHA-256 хэшіне негізделген қолтаңба. Файл өзгерсе, тексеру `INVALID` береді.

## 2. Акторлар

| Актор | Рөлі | Не істейді |
|---|---|---|
| Қол қоюшы | Құжат иесі, мысалы бөлім басшысы | Кілт жұбын жасайды, жеке кілтпен файлға қол қояды |
| Тексеруші | Құжатты алушы, мысалы басқа бөлім қызметкері | Ашық кілт пен `.sig` арқылы құжатты тексереді |
| Жүйе (Esign-Util) | Консольдік бағдарлама | Хэш есептейді, қол қояды, тексереді, кілтті PEM-мен сақтайды |

## 3. Талаптар

### Функционалдық

| № | Талап |
|---|---|
| F1 | Жүйе RSA-2048 кілт жұбын жасауы керек (`keygen`) |
| F2 | Кілттер PEM форматында сақталуы керек: жеке кілт PKCS#8, ашық кілт X.509 |
| F3 | Жүйе кез келген файлға SHA256withRSA арқылы қол қоюы керек (`sign`) және `.sig` файл жасауы керек |
| F4 | Жүйе қолтаңбаны тексеріп, `VALID` немесе `INVALID` көрсетуі керек (`verify`) |
| F5 | Файл бір байт өзгерсе, нәтиже `INVALID` болуы керек |
| F6 | Қате жағдайында (файл жоқ, PEM бүлінген, параметр жоқ) түсінікті хабар шығуы керек |

| № | Талап |

## 4. Теориялық негіз

### Электрондық қолтаңба қалай жұмыс істейді

**Қол қою:** файлдан SHA-256 хэш алынады, хэш жеке кілтпен RSA арқылы өңделіп, қолтаңба шығады.

**Тексеру:** алушы файлдан хэшті өзі есептейді, ашық кілтпен қолтаңбадан хэшті қалпына келтіріп, салыстырады. Сәйкес болса қолтаңба дұрыс.

Қолтаңба тұтастық, авторлық және бас тарта алмау қасиеттерін береді, бірақ құжатты шифрламайды, яғни құпиялылықты қорғамайды.

### Алгоритмдерді таңдау

| Параметр | Таңдау | Негіздеме |
|---|---|---|
| Асимметриялық алгоритм | RSA | JCA-да стандартты, кең таралған |
| Кілт ұзындығы | 2048 бит | NIST бойынша қазіргі ең төменгі ұсынылатын деңгей, 1024 бит әлсіз |
| Хэш | SHA-256 | MD5 және SHA-1 коллизияға осал |
| Қолтаңба схемасы | SHA256withRSA (PKCS#1 v1.5) | Тапсырма талабы; балама RSASSA-PSS теориялық тұрғыдан беріктеу |
| Кездейсоқ сан | `SecureRandom` | Криптографиялық берік генератор |

### PEM форматы

PEM дегеніміз DER байттарының Base64 түрі және тақырып жолдары.

```
-----BEGIN PRIVATE KEY-----   PKCS#8   (key.getEncoded())
-----BEGIN PUBLIC KEY-----    X.509 SubjectPublicKeyInfo
```

Оқығанда тақырыптар алынып тасталып, Base64 декодталады да, `KeyFactory` арқылы (`PKCS8EncodedKeySpec` / `X509EncodedKeySpec`) кілт қалпына келтіріледі. `BEGIN RSA PRIVATE KEY` PKCS#1 форматы, оны Java тікелей оқымайды.

## 5. Қауіптер және қорғаныс

| Қауіп | Шара |
|---|---|
| Жеке кілттің GitHub-қа түсуі | `.gitignore`: `*.pem`, `keys/`, `.env` |
| Жеке кілтті басқалардың оқуы | `rw-------` рұқсаты; нақты жүйеде пароль, KeyStore немесе HSM |
| Әлсіз хэш | Тек SHA-256 |
| Қысқа кілт | Кемінде 2048 бит |
| Тексеру қатесін елемеу | Бүлінген қолтаңба `INVALID` береді, басқа қателер `EsignException` болады |
| Ашық кілттің шынайылығы | Сертификат (X.509) қажет, бұл 12-тақырыптың мәселесі |
